# ADR-001: Technology Stack Justification

**Status:** Accepted

## Context

This project is a full-stack lake water quality monitoring platform for Lake Malawi. The system needs to handle:
- Satellite and climate data ingestion (CHIRPS, NASA POWER, Sentinel-2, MODIS, Sentinel-3)
- Geospatial processing and analysis (water extent, water quality indicators)
- Disaster alert management and evaluation
- Report generation with PDF/CSV exports
- Public-facing dashboard with anonymous read-only access
- Local model inference for disaster forecasts

## Decision Drivers

| Driver | Requirement |
|--------|-------------|
| Data processing | Heavy raster/numerical processing (xarray, rasterio, numpy, pandas) |
| Geospatial vector/raster | PostGIS extension for spatial queries, index optimization |
| API performance | FastAPI with async support for concurrent ingestion jobs |
| Type safety | End-to-end type safety from database schemas to frontend |
| Developer productivity | Rapid prototyping with good tooling and ecosystem |
| Deployment | Docker Compose for reproducible environments, single-node deployment |
| Frontend interactivity | Real-time map updates, dynamic charts, responsive UI |

## Considered Alternatives

| Technology | Why Not Chosen |
|------------|----------------|
| Node.js/Express | Python scientific ecosystem (xarray, geopandas) is more mature for raster processing; existing team expertise |
| Django | More opinionated, less control over async job processing; FastAPI better for custom API design |
| PostgreSQL without PostGIS | Spatial queries would be inefficient for lake boundary queries, coverage analysis |
| MySQL | No PostGIS support, poor raster function support |
| Ruby on Rails | No ecosystem for the required geospatial and ML libraries |
| Vue.js frontend | Team has greater expertise with React + TanStack Query ecosystem |

## Accepted Technology Stack

### Backend

| Component | Technology | Justification |
|-----------|------------|---------------|
| API Framework | **FastAPI** | - Async out of the box, ideal for concurrent ingestion workers<br>- Automatic OpenAPI/Swagger documentation<br>- Pydantic v2 integration for request/response validation<br>- Performance comparable to Node.js/Go for I/O-bound workloads |
| ORM | **SQLAlchemy 2** (typed) | - Full SQL expressiveness<br>- Strong typing with type hints<br>- Alembic for migration management<br>- PostGIS extension support for spatial data |
| Database | **PostgreSQL 16 + PostGIS 3.4** | - PostGIS provides spatial index operators `<->`, `ST_DWithin`, `ST_Intersects`<br>- Postgres handles JSONB for flexible metadata<br>- Proven reliability for 24/7 operations<br>- SQLite as zero-config fallback for local development/testing |
| Geospatial Python | **rasterio, xarray, geopandas, numpy, pandas, shapely** | - Industry-standard raster processing libraries<br>- xarray for multi-dimensional array (satellite) operations<br>- geopandas for vector/attribute joining<br>- shapely for geometric operations (buffers, intersects)<br>- numpy/pandas for numerical computing |
| Authentication | **FastAPI security utilities** | - JWT-based token authentication<br>- Password hashing with bcrypt<br>- Role-based access control (super_admin, admin, researcher) |
| Job Queue | **Database-backed polling worker** | - No external broker required (keeps deployment simple)<br>- Sufficient for single-node deployment<br>- Transient job state in same DB as data |

### Frontend

| Component | Technology | Justification |
|-----------|------------|---------------|
| UI Framework | **React 18** | - Component-driven architecture<br>- Virtual DOM for efficient updates<br>- Large ecosystem, extensive learning resources |
| Language | **TypeScript** | - Compile-time type safety<br>- Better IDE autocompletion<br>- Catches API contract errors early<br>- Essential for large codebase with multiple developers |
| Build Tool | **Vite 6** | - Fast HMR (hot module replacement)<br>- Native ES module support<br>- Significantly faster than Create Create React App |
| Styling | **Tailwind CSS 3** | - Utility-first approach for rapid UI development<br>- Responsive design built-in<br>- Reduced CSS file size (only used classes)<br>- Consistent design system across pages |
| Routing | **React Router 6** | - Standard de facto routing for React<br>- Nested routes for dashboard layout<br>- Type-safe route params with TypeScript |
| Data Fetching | **TanStack Query 5** | - Server-state management out of the box<br>- Automatic caching, refetching, stale-while-revalidate<br>- Optimistic updates for better UX<br>- Handles pagination and pagination state|
| Form Handling | **React Hook Form + Zod** | - Minimal re-renders with register/controller<br>- Zod for schema-based validation<br>- TypeScript inference from validation schemas<br>- Accessible error handling |
| Charts | **Recharts 2** | - Declarative charting for Recompose-like API<br>- Built on React<br>- Good for time-series and comparison charts |
| Mapping | **Leaflet / react-leaflet** | - Lightweight map library<br>- OSM tile usage (no licensing costs)<br>- Good compatibility with geojson data<br>- Proven in spatial applications |
| State Management | **React Context + useReducer** | - Simple global state for auth, UI preferences<br>- No Redux boilerplate needed<br>- Works well with TanStack Query|

### Deployment

| Component | Technology | Justification |
|-----------|------------|---------------|
| Containerization | **Docker Compose** | - Single-command start of all services (Postgres, backend, frontend/nginx)<br>- Volume persistence for database<br>- Environment variables via `.env` and `.env.example`<br>- Suitable for development, staging, and small-scale production |
| Frontend Server | **nginx** | - Static file serving<br>- TLS termination (in production)<br>- Reverse proxy to backend API<br>- Gzip compression, caching headers |

## Consequences

### Positive

- **End-to-end type safety:** TypeScript frontend → Pydantic models → SQLAlchemy types → PostgreSQL types
- **Rapid development:** Python ecosystem for data science, React for UI, Vite for fast iteration
- **Spatial capabilities:** PostGIS enables efficient lake-boundary queries, spatial joins, distance calculations
- **Scalable architecture:** Docker Compose for local/dev, can scale to Kubernetes or separate services later
- **Clear separation:** Frontend (React) communicates only via typed API contracts (FastAPI/OpenAPI)

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| PostGIS not available in all deployments | SQLite fallback with geometry type stored as TEXT; `app/services/spatial.py` detects availability and switches behavior |
| FastAPI async limitations for CPU-bound work | Offload heavy raster processing to dedicated worker threads; use `run_in_executor` or separate worker processes |
| Single-node job queue | Documented as adequate for single instance; future migration to Celery/RabbitMQ if needed |
| Tailwind CSS learning curve | Team upskilling via existing project examples; benefits pay off in rapid UI development |
